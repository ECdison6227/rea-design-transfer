# 风格库交付与验收

以下为建议分层，可以合并小型文档；文件名和数量不是完成标准。用户指定结构时服从用户。

```text
README.md                    单一入口、版本、证据级别、运行与阅读顺序
library.json                 本来源/多来源的可选择索引
evidence/                    原图/录屏、操作、身份、REA输出、准确源码锚
assets/                      可复用原始资产、加工版本、文案与资产清单
spec/                        设计原则、视觉/排版/布局、组件、行为、引导、motion
tokens/                      可导入CSS/JSON或目标平台等价物、来源与换算条件
reference/                   可运行独立组件与代表页面、状态演示、平台接口
comparison/                  原产品↔参考配对、环境、视觉及行为差异
transfer-example/            一种不同业务如何采用同一设计语言
docs/                        迁移指南、覆盖/缺口、下一Agent提示词、恢复记录
```

参考实现的技术栈按可迁移对象选：网页/混合界面通常React+TypeScript；Android/iOS等原生目标可用对应声明式组件或提供准确映射。若采用网页解释原生样式，标明不能验证原生字体/手势/系统层。不要强行要求所有平台产出同一种运行工程。

以上是完整风格库的交付形态。若用户明确只委托原始资料整理、风格片段或选型评估，可以只交对应规范/索引/映射，并列出缺失运行、参考和对照；不能为了满足模板虚构这些产物，也不能自行缩小用户要求的完整研究范围。

## library.json：用于以后选择风格

每个来源profile建议包含以下信息，空缺可以为null/unknown：

- `id/name/source/versions/platforms/deploymentModes`：来源与适用边界。
- `traits`：有依据的密度、排版、导航、内容组织、反馈与引导特征；每项关联依据或标C。
- `goodFit/needsAdaptation`：适合的产品场景及需适配内容，标为建议而非事实。
- `artifacts`：代表场景缩略图/原图入口、资产清单、tokens、规范、参考入口、对照、接入指南的相对路径；缩略图为派生展示，不替代原始证据。
- `coverage/unknowns`：可用、部分、未验证，指出关键风险和优先补证点。

多来源索引只引用各自profile，明确比较轴。不要用“高级/好看”等空泛标签作为唯一选型依据，也不要没有证据就给相似度分数。

## 可复用资产交接

必须交付研究范围内可获取的图标、字体、文字文案/本地化资源、图片、插画、动效等资产及可查清单，供下一Agent直接定位和复用。建议原件放 `assets/original/`、加工版本放 `assets/derived/`，清单用JSON或表格；可沿用来源结构，但不能只给截图、外部URL或文件名。

- 原件保持原始格式与内容；内嵌资产保留源码片段和准确位置。转换、裁剪、重绘、改写版本另存并关联原件。
- 清单至少包含资产标识、类型、保存路径、来源包路径/URL与版本、SHA-256、用途及引用页面/组件、主题/尺寸/状态变体、实际使用证据或未确认状态。文案另记原文/资源键、语言、占位符和出现条件。
- 无法提取或缺少的资产写入缺口，说明原因、已保留的证据及补取方法；独立重绘或替代品标D，不能冒充原件。
- README、profile和迁移指南提供资产入口及引用/替换方法。迁移时改写文案、替换品牌或适配字体不删除、不覆盖研究库原件；研究留存与公开分发范围分别记录。

## 组件与事件契约

组件规格应让下一个Agent知道：输入props/数据形状、受控/非受控状态、允许的转移、事件与触发顺序、副作用归属、焦点/键盘/手势、可用/禁用/忙碌/错误、取消与重入、长文本/缩放/主题、平台边界、来源和未知。

将“画成什么”与“什么时候出现、点击后怎样”连在一起。例如可取消异步操作要分别说明UI停用、请求取消、晚到结果、重试保留的数据；未证实的部分作为D策略实现，而非补造原行为。

弹窗与页面切换交付可执行的状态机或转移表，按适用性写明“当前页面/状态→触发动作与前置条件→弹窗/目标页面→副作用→关闭/返回结果与保留/重置状态→证据/未知”。覆盖已研究的打开、确认、取消、外部关闭、叠层优先级，以及首次进入、重选、返回、拦截、加载和失败路径；交接时能据此实现行为，未验证的路径明确标注。

最小规则结构示例（字段内容应来自本次证据，不照抄示例值）：

```json
{
  "id": "rule.navigation.return-state",
  "statement": "返回列表时保留哪些状态",
  "appliesWhen": "明确页面和运行条件",
  "classification": "A|B|C|D",
  "evidence": ["本项目实际定位编号或真实REA ID"],
  "implementation": "状态所有者及事件契约",
  "exceptions": [],
  "unknowns": [],
  "comparison": "原版与参考的核对位置"
}
```

JSON/CSS tokens也保留来源、条件和原单位；来源元数据可放sidecar，不要求把长记录塞入每条CSS变量。别名和跨平台换算属于D选择，即使它引用B事实。

## 对照与迁移演示

**来源对照**：原产品和参考使用相同的可确认窗口/设备画布、主题、语言、数据与状态；无法一致时逐项记录。原图不改；叠图、标注、裁切另存并标为派生产物。记录具体对齐/字形/焦点/交互偏差，不以单一分数宣称还原。

**跨业务演示**：选择一种不同业务，例如文件/任务/资料管理，复用排版层级、组件组合、动作位置、状态反馈、校验、空态及引导策略。明确哪些业务词、图表、品牌资产或规则被替换。一个与原App相同的页面复刻不足以证明通用迁移能力。

两种验证不能互相替代。参考测试只证明参考实现的行为；借鉴效果需要来源对照，迁移可用性需要不同业务样本。

## 交接验收

- README让新Agent不读聊天也能识别目标、证据类型、环境、阅读顺序、启动命令和已知缺口。
- 约定的代表页/组件能从A/B证据追到规则、D实现与对照；缺少A时明显标部分验证。
- 视觉、交互、行为、用户引导都有可实施说明，不是只有截图或配色。
- 可复用资产原件、加工版本、文案及清单可定位，引用位置与状态变体可查；提取缺口明确，业务替换不覆盖原件。
- 弹窗触发/关闭/叠层与页面跳转/返回/状态保留有转移记录、证据和验证结果，未测路径明确标注。
- 新业务替换与固定保留边界明确，目标平台接口和字体替换影响可查。
- 原图身份、源码位置/哈希、实际REA输出、选源与预算限制可复核。
- 覆盖表逐项区分verified/partial/unverified/not-applicable，不以文件量或模板字段齐全作为完成证明。
- 有恢复记录；分享内容不依赖本机私有路径/未包含依赖。不要把参考资料的README复制后当自己的交付入口。
- `docs/next-agent-prompt.md`明确要求：读取库→审查目标项目→做规则映射→实施→检查差异，保留目标产品功能与品牌，列出独立选择。

若用户未明确要求发布GitHub，先准备可审查的本地仓库，不擅自公开。发布时排除用户profile、凭据、私人会话和不宜分发资产；不把发布操作当完成研究的必要前提。
