# 研究维度与平台路线

按目标和可达场景选取维度；不把下列所有状态强套到所有组件。先完成关键模式，再按缺口扩展。

## 1. 平台路线

| 目标 | 入口与相关证据 | 运行核对与平台差异 |
|---|---|---|
| Android | 按REA技能的APK/DEX路由；当前布局、drawable/selector、字体、原生类、RN/Hermes/WebView资源；依调用链确定当前分支 | 真机或实际支持的模拟器运行原APK；设备密度/字体缩放、系统栏、返回手势、键盘、权限、触摸反馈。没有匹配CPU架构/运行环境时不能把安装完成当运行成功 |
| iOS/iPadOS | 按可获得制品与REA能力检查资源/原生或混合层，说明签名、加密与解析范围 | 只使用可正常运行的设备/模拟器版本；safe area、动态字体、导航返回、sheet和键盘。平台不支持时记录缺口，不默认要求越狱/绕过签名 |
| 桌面 | 先识别原生、Electron、.NET、Flutter、Qt等，再按REA技能路由；不要仅凭EXE或ASAR后缀决定整个渲染架构 | 实际安装窗口；记录原生壳/网页客户区、DPI、应用zoom、鼠标hover、键盘focus、快捷键、resize和系统主题。真实工具不支持Windows native UI时可使用经目标校验的系统API，并标独立采集来源 |
| 网站/Web App | 按REA浏览器指南选实际页面及加载的脚本/样式；保留URL/捕获时间/构建或资产哈希 | 浏览器实际页面、DOM/可访问性/计算样式和截图；viewport/DPR/zoom、登录态、响应式、滚动/路由/History、触摸与键盘。需要主动操作时使用当前实际支持的交互工具，不能把被动采集称点击 |

这里只负责选研究问题，工具名和参数以当前REA技能与实际schema为准。未分析依赖不能因存在于包内就自动视为当前运行代码。选中模块的语义预算/超时/截断与全包未选范围要区分。

同一窗口、设备或页面的主动操作保持单一控制者；并行工作可拆为静态追踪、证据整理和独立参考实现，不要同时驱动同一GUI而破坏状态和时间归因。共享配置与证据文件的修改也需要协调。

## 2. 产品家族感：先观察规则，再概括理由

梳理信息密度、层级、留白、内容宽度、标题角色、导航方式、操作强调、内容/工具区分、选择/编辑/浏览的边界、反馈强弱、用语与引导节奏。

每条原则至少说明：规则是什么；在哪些场景看到；何时适用；例外/反例；可迁移部分；原业务专属部分。证据不足时只称候选原则。比如“所有动作都弹窗确认”若只看到删除确认，不能泛化；“大标题很轻”也不能推成表格列标题同样轻。

作者意图与因果理由多数不是界面直接可读的事实。可以写“推断此结构便于……”，不要写“设计师为了……”冒充直接证据。

## 3. 视觉与排版

- 语义色：页面/容器/浮层层级，主次/禁用文字，品牌动作与系统accent，状态、边框、mask、hover/pressed/selected/focus；保留合成、透明度及主题/局部覆盖。
- 字体：family声明→资源哈希→运行报告→可确认的字形覆盖；中西文和数字分工、字重/变量轴、字号/行高/字距、基线与font padding。字体替换是迁移决策，需要重新对照。
- 尺度：布局grid、gutter、对齐、间距、宽高、最小触控/点击区、density、内容measure、长文本、窄屏/横屏/折叠/大字；明确逻辑与物理坐标。
- 表面：普通与平滑圆角、border、阴影、分隔、图标stroke/fill、状态图标；区分源码文件存在与当前实例实际使用。

tokens保留语义、条件、来源和原单位；未知的全局shadow/radius/motion值不要补造。像素采样是合成结果，不自动等于computed style。

## 4. 组件与行为

首轮从来源中选择基础组件，例如按钮/图标按钮、输入器/表单、导航/Tab、列表/卡片、菜单/选择器、弹窗/sheet、Tooltip/提示、Toast/状态反馈、搜索、引导组件。实际只有少数组件的目标可以减少，不能借重复变体充数。

对每个组件记录结构与插槽、尺寸与排版、适用状态、事件/副作用、键盘与手势、focus/selection、禁用语义、与父组件/路由的边界。状态按适用性研究default、hover、pressed、focus、disabled、loading、selected、invalid、empty、error；标明不适用和未验证。

软件行为至少围绕关键体验追踪：

- 导航/返回/重选/深链，滚动和筛选状态是否保留。
- 编辑/草稿/保存/取消、脏数据、离开确认、撤销。
- 提交/加载/生成/停止/完成、重复触发、失败/重试、晚到结果、刷新/缓存/离线。
- 菜单方向键、嵌套层、外侧点击、Escape/系统返回优先级、弹窗焦点恢复。
- 输入法组合态、Enter/换行、校验时机、搜索防抖及清空。
- 用户/设备/账号/权限改变后哪些状态失效或重置。

只保留对设计语言和用户体验有作用的机制；领域数据模型/算法默认只列边界。停止按钮出现不证明网络取消，颜色灰不证明无法点击，方法名不证明实现语义。

## 5. 用户引导与内容设计

将“用户指引”作为交付主体，包含：

| 模式 | 要回答的问题 |
|---|---|
| 首次使用 | 用户何时看到、能否跳过、第一步价值如何呈现、完成状态如何保存、何时再出现 |
| 渐进披露/功能发现 | 新手先看到什么，高级能力在何处出现，提示频率、关闭/不再提示、版本变化 |
| 上下文说明 | 标签、Tooltip、辅助文字、示例和帮助链接的层级；何时用内联说明/弹层 |
| 空态 | 空的原因、是否区分首次/无结果/权限不足，提供什么下一步而非仅装饰图 |
| 权限 | 何时解释用途、何时真正请求、拒绝/永久拒绝/稍后处理、重返路径 |
| 校验/错误 | 发生时机、信息具体性、输入保留、可恢复操作、重试与联系帮助 |
| 风险动作 | 何时确认、何时可撤销、默认焦点与按钮顺序、取消路径 |
| 熟练使用 | 快捷键、搜索、命令入口、批量/重复操作、提示如何不干扰熟练用户 |

记录原文或短摘录时注意来源与隐私；迁移时写同样语气和信息结构的新文案，不把原业务词或品牌身份误留在自己的软件里。

## 6. 动画与反馈

逐动作记录触发、属性、起止值、duration/delay/easing或可证实spring参数、手势阈值、重入/中断、退出挂载、滚动联动、触觉/声音、系统和应用级reduced motion。

有时间记录的采集和当前源码互证。采集调用自身的耗时、实际采样窗口、时钟与丢帧要保留；稀疏截图只能给出观察区间。DOM/WPF/原生UIA在能力上不同，不强行制造统一测量精度。

## 7. 原图身份与最小证据记录

每次采集至少关联scene、capture时间/时间区间、target身份、运行模式、操作序列、窗口或设备大小、主题/语言/缩放条件、文件路径、SHA-256、采集方法、有效性与限制。网页没有EXE哈希时记录URL及捕获资产身份，不编造应用版本。

每条规范关联A运行记录或B文件哈希+位置/选择器/函数；C写推断链，D写选择与验证方式。一个token或组件可同时有A/B支持，但不能把B的duration升级为A实测。

复用历史资料时附加 `origin: historical`、原采集时间、本轮复核时间和身份/条件匹配结论；本轮新采集才用`origin: current`。复制文件或查看旧截图不产生新实测。元数据缺少主题选择、DPI、zoom或操作序列时如实记缺失，不能根据文件名或一般默认值补全。只有少数A截图的研究，其余行为和主题仍可能为部分/未验证。

## 8. 阻塞处理

先判断问题在目标身份、工具连接、平台后端、设备、正常认证、配置还是采集方法。已有正常运行路径就用；按官方支持方式配置本地网关/测试数据时声明前端与数据身份。不要把另一平台或旧版本画面无条件替代目标。

没有运行条件时继续可支持静态部分，保留待测场景与具体补证方法。研究可交付为部分成果，不能用独立演示填充A证据，也不能为了“必须运行”突破授权或绕过访问控制。
